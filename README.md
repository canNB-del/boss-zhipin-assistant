# Boss 直聘应聘助手

面向所有求职者的 Edge / Chrome 扩展。用户自行填写背景资料，读取或粘贴 HR 问题，生成回复草稿并填充 BOSS 聊天输入框，最后手动确认发送。

## 安装

1. 下载并解压源码。
2. 在 Edge 打开 `edge://extensions/`，或在 Chrome 打开 `chrome://extensions/`。
3. 开启开发人员模式，选择“加载解压缩的扩展”，选择包含 `manifest.json` 的文件夹。
4. 登录 BOSS 直聘；更新扩展后，在扩展管理页重新加载，再刷新 BOSS 页面。

## 自行填写个人资料

- 初始资料全部为空，没有预设姓名、学历、工作经历或技能。
- 可以填写称呼（选填）、教育背景、工作或项目经历、技能与优势、求职意向与可用时间。不确定的内容可以留空。
- 点击“保存个人资料到本机”后，资料保存在当前浏览器的扩展本地存储中，不会同步到 GitHub 或其他用户的浏览器。该存储不是加密保险箱。
- 点击“清除本机求职数据”可删除已保存的个人资料、岗位队列、自定义模板，并清空当前弹窗的问题、回复和密钥输入框。
- 从早期版本升级时，旧的打招呼模板会重置为通用模板，岗位队列保留。

## 导入简历并覆盖资料

1. 在“导入简历并覆盖个人资料”中选择 PDF、DOCX、TXT 或 MD 文件（最大 10 MB；PDF 最多 30 页）。
2. 等待本机解析。预览中可编辑称呼、教育背景、经历、技能和求职意向，并展开原文核对。
3. 点击“确认覆盖并保存个人资料”。这是完整替换：预览中的空白字段也会清空原字段。旧打招呼模板及岗位清单不受影响；旧的候选回复草稿会清空。
4. 本次弹窗关闭前，可点击“撤销上次简历覆盖”恢复覆盖前的资料；取消导入或解析失败不会修改原资料。

解析不需要 API Key，不联网传输简历。PDF.js 及中文字符映射随插件一起提供。原始文件、提取原文及待确认预览只在本次弹窗中临时使用，不写入扩展存储；确认后仅保存个人资料字段。之后点击“生成回复”，这些资料才会随问题发送给 OpenAI。

v0.5.0 改进了常见模板的识别：

- 支持“技术能力”“核心能力”等标题，以及带空格、括号、Markdown 标记的中英文分节标题。自我评价中的求职目标、到岗时间等单独归入求职意向。
- 除“姓名/Name”标签外，也识别简历顶部符合姓名格式的独立文字；这类称呼会提示核对，不确定时留空。
- 联系方式按片段移除，同一行的学历、意向岗位等信息保留。仍需核对原文中的其他个人信息。
- PDF 根据文字坐标重建行序、合并相邻中文碎片；检测到常见双栏时按分栏顺序读取，并提示核对。复杂跨栏、旋转文字或表格仍可能不准确。
- DOCX 读取正文及页眉，避免嵌套文本框重复提取，并跳过标记删除的文字。
- 无法确定归属的文字显示在“待归类内容”，不会自动混入工作经历。请将需要的内容移到对应字段，删除不需要的内容，清空待归类框后再保存，避免静默遗漏。

以上为本机规则解析，仍需核对结果。图片/扫描 PDF 不支持 OCR；加密文档需先解除密码，旧版 DOC 请另存为 DOCX。

本功能覆盖插件内的个人资料，不会修改 BOSS 在线简历，也不会把附件发给 HR。有关 PDF.js 的许可见 `THIRD_PARTY_NOTICES.md`。

## 回复 HR

1. 打开 BOSS 聊天窗口和扩展，填写自己的资料。
2. 输入自己的 OpenAI API Key，以及该 API 账户可使用的模型名称。API 使用及费用由用户自行配置。
3. 点击“读取当前页面”，核对读取结果；也可以选中网页上的问题再读取，或直接粘贴问题。
4. 点击“生成回复”。本次填写的个人资料及问题将发送至 OpenAI API，资料为空时模型会提示补充信息。
5. 检查、编辑草稿，点击“填充到 BOSS 输入框”，再由用户手动点击 BOSS 的发送按钮。

API Key 仅在当前弹窗内使用，不写入扩展存储；关闭弹窗后需重新输入。问题和生成的草稿也不持久保存。插件直接调用 OpenAI API，不接入某条 Codex 对话，也没有开发者自建的数据收集服务。

页面读取使用通用选择器，尚不能可靠区分 HR 和求职者消息，必须核对后再生成；BOSS 改版也可能影响读取和填充。

## 岗位清单与打招呼

支持导入用户自行准备的 JSON 或 CSV（支持引号包裹、字段中的逗号与换行）。字段为 `company`、`job`、`url`、可选 `status`。只接受 `https://www.zhipin.com/` 下的链接，按完整链接去重。也可以点击“加入当前职位”。

JSON 格式示例：

```json
[
  {
    "company": "示例公司",
    "job": "目标岗位",
    "url": "https://www.zhipin.com/",
    "status": "待处理"
  }
]
```

打开岗位并进入沟通窗口后，点击“填充当前职位消息”。模板中的 `{job}` 会替换成岗位名称。模板可自行编辑，初始模板不含任何个人经历。

当前仅记录“已打开”状态，尚未实现发送状态识别。扩展不会自动发送消息或绕过验证码。

输入框已有其他草稿时，插件会拒绝覆盖；请先保存或清空原文。页面中找不到唯一输入框时，请手动复制草稿。

## 当前验证范围

v0.5.0 已检查 JavaScript 语法、扩展清单和个人资料的本地保存、恢复、清除行为，使用模拟接口验证生成请求。在浏览器测试页验证 TXT、DOCX、中英文 PDF、页眉和嵌套文本框解析，以及空文件、损坏 DOCX、无文字 PDF、超限文件和旧版 DOC 的拒绝处理；验证待归类拦截、确认覆盖、撤销及保存失败时保留旧资料。另在本机验证了现有简历文件，原文件和结果均未加入仓库。

仓库内提供虚构样例的规则回归测试，可运行 `node resume-parser.test.cjs`，覆盖字段归类、顶部姓名、混排联系方式、PDF 中文碎片、双栏和右对齐日期。浏览器测试页使用模拟扩展存储；上述测试不等同于真实扩展端到端验证。

尚未使用真实 API Key 调用生成服务，也未在登录后的 BOSS 聊天页面完成端到端验证。请在 Edge/Chrome 重新加载插件后先用自己的简历核对解析结果。

项目与 BOSS 直聘无官方关联。仓库暂未指定开源许可证，公开可见不等同于授予再分发或商用许可。

## 源码与本地数据

仓库仅包含通用源码和说明，不包含用户简历、联系方式、真实岗位清单、聊天记录或 API Key。用户在浏览器中填写和保存的数据不会修改源码文件。
