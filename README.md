# Boss 直聘应聘助手

面向所有求职者的 Edge / Chrome 扩展。用户可上传简历自动保存资料，或选择手动填写，再读取或粘贴 HR 问题，生成回复草稿并填充 BOSS 聊天输入框，最后手动确认发送。

## 安装

1. 下载并解压源码。
2. 在 Edge 打开 `edge://extensions/`，或在 Chrome 打开 `chrome://extensions/`。
3. 开启开发人员模式，选择“加载解压缩的扩展”，选择包含 `manifest.json` 的文件夹。
4. 登录 BOSS 直聘；更新扩展后，在扩展管理页重新加载，再刷新 BOSS 页面。

## 选择个人资料来源

插件提供两种方式，任选其一即可：

- **上传简历自动覆盖**：选择文件后，在本机自动解析、覆盖并保存，无需再填写表单、整理分节或点击确认保存。完成后可直接生成 HR 回复。
- **手动填写**：填写称呼、教育背景、工作或项目经历、技能与优势、求职意向、补充信息，点击“保存手动填写的资料”。没有的信息可以留空。

两种方式共用当前个人资料。切换方式不会删除资料；也可以切换到手动填写，对已导入的信息进行可选修改。选择的方式和已保存资料会在下次打开时恢复。初始资料全部为空，没有预设个人信息。

## 上传简历自动覆盖

1. 选择“上传简历自动覆盖”，再选择 PDF、DOCX、TXT 或 MD 文件（最大 10 MB；PDF 最多 30 页）。
2. 保持插件窗口打开，等待显示“导入成功，无需手动填写”。这时资料已自动保存，可直接生成回复。
3. 可选展开“查看当前资料”，或在本次弹窗关闭前点击“撤销上次简历覆盖”，恢复导入前的资料。

导入成功会完整替换旧资料，简历中没有识别到的字段保持空白，不保留旧简历的同名字段，也不编造信息。没有明确分节的文字自动保存为“补充信息”，一并用于生成回复，无需手动归类。解析或保存失败时保留原资料。导入期间暂停资料编辑及生成回复，避免新旧资料混用；旧的候选回复在导入成功时清空。

解析不需要 API Key，不联网传输简历。PDF.js 及中文字符映射随插件一起提供。原始文件和完整提取原文仅临时使用；保存的是分类后的资料字段和未分节的补充信息。之后点击“生成回复”，这些资料才会随问题发送给 OpenAI。

解析支持“技术能力”“核心能力”等中英文分节标题、简历顶部姓名、混排联系方式、DOCX 页眉和嵌套文本框，以及常见 PDF 双栏。联系方式按片段移除，同一行的其他资料保留。复杂跨栏、旋转文字和表格仍可能有误，可选择查看资料或手动修改。图片/扫描 PDF 不支持 OCR；加密文档需先解除密码，旧版 DOC 请另存为 DOCX。

资料保存在当前浏览器的扩展本地存储中，不会同步到 GitHub 或其他用户的浏览器；该存储不是加密保险箱。点击“清除本机求职数据”可删除资料、资料来源选择、岗位队列、自定义模板，并清空当前弹窗的问题、回复和密钥。升级时原有资料保留；早期个性化原型的打招呼模板会一次性重置为通用模板。

本功能覆盖插件内的个人资料，不会修改 BOSS 在线简历，也不会把附件发给 HR。有关 PDF.js 的许可见 `THIRD_PARTY_NOTICES.md`。

## 回复 HR

1. 打开 BOSS 聊天窗口和扩展，上传简历自动保存资料，或选择手动填写并保存。
2. 输入自己的 OpenAI API Key，以及该 API 账户可使用的模型名称。API 使用及费用由用户自行配置。
3. 点击“读取当前页面”，核对读取结果；也可以选中网页上的问题再读取，或直接粘贴问题。
4. 点击“生成回复”。本次填写的个人资料及问题将发送至 OpenAI API，资料为空时模型会提示补充信息。
5. 检查、编辑草稿，点击“填充到 BOSS 输入框”，再由用户手动点击 BOSS 的发送按钮。

API Key 仅在当前弹窗内使用，不写入扩展存储；关闭弹窗后需重新输入。问题和生成的草稿也不持久保存。插件直接调用 OpenAI API，不接入某条 Codex 对话，也没有开发者自建的数据收集服务。

页面读取使用通用选择器，尚不能可靠区分 HR 和求职者消息，必须核对后再生成；BOSS 改版也可能影响读取和填充。

## 岗位清单与打招呼

支持导入用户自行准备的 JSON 或 CSV（支持引号包裹、字段中的逗号与换行）。字段为 `company`、`job`、`url`、可选 `status`。只接受 `https://www.zhipin.com/` 下的链接，按完整链接去重。也可以点击“加入当前职位”。

JSON 格式示例：

```json
[
  {
    "company": "示例公司",
    "job": "目标岗位",
    "url": "https://www.zhipin.com/",
    "status": "待处理"
  }
]
```

打开岗位并进入沟通窗口后，点击“填充当前职位消息”。模板中的 `{job}` 会替换成岗位名称。模板可自行编辑，初始模板不含任何个人经历。

当前仅记录“已打开”状态，尚未实现发送状态识别。扩展不会自动发送消息或绕过验证码。

输入框已有其他草稿时，插件会拒绝覆盖；请先保存或清空原文。页面中找不到唯一输入框时，请手动复制草稿。

## 当前验证范围

v0.6.0 已检查 JavaScript 语法、扩展清单和两种资料来源的显示、保存与恢复。浏览器测试页验证上传后自动保存、无需手动填写、补充信息保留、失败时保留旧资料、撤销和模式切换。测试页使用模拟扩展存储。

可运行 `node profile-flow.test.cjs` 验证自动导入后直接生成回复、补充信息随请求使用、重新打开恢复、手动保存、完整替换、解析/保存失败、导入期间禁用操作、撤销及清除行为。运行 `node resume-parser.test.cjs` 验证分节归类、姓名、联系方式、PDF 双栏、中文碎片和右对齐日期；样例均为虚构数据。PDF/DOCX/TXT 的提取及无效文件处理已在本机测试，私人原文件和结果未加入仓库。上述测试不等同于真实扩展端到端验证。

尚未使用真实 API Key 调用生成服务，也未在登录后的 BOSS 聊天页面完成端到端验证。请在 Edge/Chrome 重新加载插件后重新导入简历。

项目与 BOSS 直聘无官方关联。仓库暂未指定开源许可证，公开可见不等同于授予再分发或商用许可。

## 源码与本地数据

仓库仅包含通用源码和说明，不包含用户简历、联系方式、真实岗位清单、聊天记录或 API Key。用户在浏览器中填写和保存的数据不会修改源码文件。
