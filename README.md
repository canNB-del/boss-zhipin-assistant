# Boss 直聘应聘助手

面向所有求职者的 Edge / Chrome 扩展。用户可上传简历自动保存资料，或选择手动填写，再读取或粘贴 HR 问题，生成回复草稿并填充 BOSS 聊天输入框，最后手动确认发送。

## 安装

1. 下载并解压源码。
2. 在 Edge 打开 `edge://extensions/`，或在 Chrome 打开 `chrome://extensions/`。
3. 开启开发人员模式，选择“加载解压缩的扩展”，选择包含 `manifest.json` 的文件夹。
4. 登录 BOSS 直聘；更新扩展后，在扩展管理页重新加载，再刷新 BOSS 页面。

## 页面浮窗与密钥保留（v0.7.4）

点击工具栏的插件图标，在 BOSS 页面右上角打开小浮窗，不创建独立窗口。没有全屏遮罩，可继续点击、输入和滚动旁边页面；点击外部、切换焦点、按 Escape 或再次点击插件图标都不会关闭或重建浮窗。只有顶部“关闭浮窗”按钮会主动关闭它。刷新同一 BOSS 标签页后会恢复已打开的浮窗；已手动关闭的则保持关闭。标签页关闭、离开 BOSS 网站或退出浏览器会结束该页面，未保存的问题和草稿不会跨刷新保留。

读取和填充绑定浮窗所在的 BOSS 标签页，切换到其他标签页不会改变原浮窗的目标。从其他网页点击图标时，会切换到最近访问的 BOSS 标签页并显示浮窗；尚未打开 BOSS 时，会先打开 BOSS 首页。更新后请在扩展管理页重新加载插件，再刷新 BOSS 页面以加载浮窗脚本。

API Key 输入或手动替换后自动保存在当前浏览器的扩展本地存储，关闭再打开仍会恢复；也可点击“保存接口设置”。无需每次输入。密钥绑定最终 API 请求地址：更换到其他接口时输入框清空，不会自动把原密钥发到新地址；新接口需手动填入对应密钥。点击“清除已保存密钥”可删除保存值。“清除本机求职数据”保留接口设置和密钥。

密钥仅在密码框中显示，以本地存储形式保存（并非系统加密保险箱），不使用同步存储，不写入源码或 Git。扩展将本地存储访问限定为受信任的扩展上下文，BOSS 页面内容脚本不能读取密钥。

## 选择个人资料来源

插件提供两种方式，任选其一即可：

- **上传简历自动覆盖**：选择文件后，在本机自动解析、覆盖并保存，无需再填写表单、整理分节或点击确认保存。完成后可直接生成 HR 回复。
- **手动填写**：填写称呼、教育背景、工作或项目经历、技能与优势、求职意向、补充信息，点击“保存手动填写的资料”。没有的信息可以留空。

两种方式共用当前个人资料。切换方式不会删除资料；也可以切换到手动填写，对已导入的信息进行可选修改。选择的方式和已保存资料会在下次打开时恢复。初始资料全部为空，没有预设个人信息。

## 上传简历自动覆盖

1. 选择“上传简历自动覆盖”，再选择 PDF、DOCX、TXT 或 MD 文件（最大 10 MB；PDF 最多 30 页）。
2. 保持插件窗口打开，等待显示“导入成功，无需手动填写”。这时资料已自动保存，可直接生成回复。
3. 可选展开“查看当前资料”，或在本次助手窗口关闭前点击“撤销上次简历覆盖”，恢复导入前的资料。

导入成功会完整替换旧资料，简历中没有识别到的字段保持空白，不保留旧简历的同名字段，也不编造信息。没有明确分节的文字自动保存为“补充信息”，一并用于生成回复，无需手动归类。解析或保存失败时保留原资料。导入期间暂停资料编辑及生成回复，避免新旧资料混用；旧的候选回复在导入成功时清空。

解析不需要 API Key，不联网传输简历。PDF.js 及中文字符映射随插件一起提供。原始文件和完整提取原文仅临时使用；保存的是分类后的资料字段和未分节的补充信息。之后点击“生成回复”，这些资料才会随问题发送到你配置的 AI 服务。

解析支持“技术能力”“核心能力”等中英文分节标题、简历顶部姓名、混排联系方式、DOCX 页眉和嵌套文本框，以及常见 PDF 双栏。联系方式按片段移除，同一行的其他资料保留。复杂跨栏、旋转文字和表格仍可能有误，可选择查看资料或手动修改。图片/扫描 PDF 不支持 OCR；加密文档需先解除密码，旧版 DOC 请另存为 DOCX。

资料保存在当前浏览器的扩展本地存储中，不会同步到 GitHub 或其他用户的浏览器；该存储不是加密保险箱。点击“清除本机求职数据”可删除资料、资料来源选择、岗位队列、自定义模板，并清空当前窗口的问题和回复，保留接口设置和密钥。升级时原有资料保留；早期个性化原型的打招呼模板会一次性重置为通用模板。

本功能覆盖插件内的个人资料，不会修改 BOSS 在线简历，也不会把附件发给 HR。有关 PDF.js 的许可见 `THIRD_PARTY_NOTICES.md`。

## 配置 AI 接口（官方、中转站或其他厂商）

v0.7.4 支持自行填写 **OpenAI 兼容的 Chat Completions 接口**，不再固定请求 OpenAI 官方域名。

### 自动获取并填写模型

先填写接口地址和 API Key，点击“获取模型列表”，无需提前填写模型名称。插件会请求该服务商的模型列表，展示去重排序后的模型 ID。可输入关键词搜索，再从下拉框选择；选中后自动填写并保存地址与模型，下次打开仍可使用。也可以随时手动输入模型名称。

列表通过与聊天接口同一路径前缀下的 `GET /models` 获取。例如 `https://relay.example/v1` 或完整的 `https://relay.example/v1/chat/completions` 都会读取 `https://relay.example/v1/models`；自定义前缀也会保留。请求只携带该服务商的 Bearer API Key，不发送简历或 HR 问题。模型列表不持久保存，密钥保存在本机；更换地址或密钥后会清空当前列表，需重新获取。

服务商需要返回 OpenAI 兼容的 `{ "data": [{ "id": "模型名称" }] }`，也接受直接返回模型对象数组。接口不存在、密钥无权限、列表为空或网络失败时，会显示错误并保留原来的手动模型，不会自动改用其他服务。模型列表可能含图像、语音或嵌入模型，能列出不代表支持聊天；请选聊天模型后点击“测试连接”。

### 更新后提示权限不在清单中

如果显示 `Only permissions specified in the manifest may be requested`，表示浏览器在域名授权阶段拒绝了请求，尚未连接服务商。这与密钥是否正确无关。

替换扩展文件后，必须打开 `edge://extensions/` 或 `chrome://extensions/`，找到本扩展并点击“重新加载”，再重新打开插件；只刷新 BOSS 页面不会重新加载扩展清单。请勿卸载，以免丢失本机资料。v0.7.1 在顶部显示界面版本与浏览器加载版本；二者不一致时会提示重载。若仍报错，请核对扩展管理页的安装路径，确认加载的是本次更新的解压文件夹，其中的 `manifest.json` 包含 `optional_host_permissions`。不要只复制 `popup.js` 或 `popup.html`。

更新后再次点击“测试连接”，按浏览器提示授权所填域名。该修正只处理权限清单与重载诊断，不代表已经验证某家中转站的密钥、模型或接口协议。

1. 在“接口地址 / Base URL”填入服务商提供的 API 地址。默认值为 OpenAI 官方地址，可以直接修改。
2. 输入该服务商对应的 API Key，点击“获取模型列表”并选择模型，或手动输入服务商提供的模型 ID。不会自动换成其他模型。
3. 密钥输入后自动保存。可点击“保存接口设置”记住地址、模型和密钥，或直接点击“测试连接”/“生成回复”。下次打开会恢复设置，需要换密钥时手动修改即可。
4. 首次请求某个接口域名时，浏览器会请求该域名的访问授权；拒绝授权不会发出请求。扩展仅在需要时申请所选域名，不在安装时获取所有网站的访问权限。
5. 可点击“测试连接”验证地址、密钥和模型；测试只发送一条测试文字，不发送个人资料或 HR 问题。测试可能按服务商规则产生少量 API 费用。

地址填写示例（`example` 域名仅为格式示例，请换成服务商的实际地址）：

| 填写的地址 | 实际请求地址 |
| --- | --- |
| `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| `https://relay.example` | `https://relay.example/v1/chat/completions` |
| `https://relay.example/v1` | `https://relay.example/v1/chat/completions` |
| `https://vendor.example/compatible-mode/v1` | `https://vendor.example/compatible-mode/v1/chat/completions` |
| `https://relay.example/api/chat/completions` | 保持这个完整接口地址 |

界面会显示最终请求地址。请填 API 地址，不是服务商首页、登录页或网页聊天地址。在线服务需要 HTTPS；本机服务也可填写 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`。地址内不能携带账号、密码、查询参数或片段，密钥请单独填写。

服务必须支持 Bearer API Key、`model`/`messages` JSON 请求和 `choices[0].message.content` 非流式回复；当前不直接支持 Anthropic 原生 Messages、Gemini 原生接口或 Responses 格式，应使用相应服务商提供的 OpenAI 兼容入口。协议参考 [OpenAI Docs：Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

生成回复时，资料、问题和密钥只会发到界面显示的接口。更换中转站或厂商也会更换接收这些数据的服务方，请使用你信任的服务。请求禁止自动跟随重定向；不会在失败后自动重试、换模型或转回 OpenAI 官方。超时为 60 秒，接口错误会显示在设置下方。各服务商的模型权限、额度和费用由用户自行配置。清除本机求职数据会保留接口地址、模型和密钥；密钥可单独清除。

## 回复 HR

1. 打开 BOSS 聊天窗口和扩展，上传简历自动保存资料，或选择手动填写并保存。
2. 配置接口地址、该服务商的 API Key 和模型名称。
3. 点击“读取当前页面”，核对读取结果；也可以选中网页上的问题再读取，或直接粘贴问题。
4. 点击“生成回复”。当前资料及问题会发送到界面显示的 API 接口；资料不足时模型会提示补充信息。
5. 检查、编辑草稿，点击“填充到 BOSS 输入框”，再由用户手动点击 BOSS 的发送按钮。

问题和生成的草稿不持久保存，API Key 保存在当前浏览器。插件不接入某条 Codex 对话，也没有开发者自建的数据收集服务。页面读取使用通用选择器，尚不能可靠区分 HR 和求职者消息，必须核对后再生成；BOSS 改版也可能影响读取和填充。

## 岗位清单与打招呼

支持导入用户自行准备的 JSON 或 CSV（支持引号包裹、字段中的逗号与换行）。字段为 `company`、`job`、`url`、可选 `status`。只接受 `https://www.zhipin.com/` 下的链接，按完整链接去重。也可以点击“加入当前职位”。

JSON 格式示例：

```json
[
  {
    "company": "示例公司",
    "job": "目标岗位",
    "url": "https://www.zhipin.com/",
    "status": "待处理"
  }
]
```

打开岗位并进入沟通窗口后，点击“填充当前职位消息”。模板中的 `{job}` 会替换成岗位名称。模板可自行编辑，初始模板不含任何个人经历。

当前仅记录“已打开”状态，尚未实现发送状态识别。扩展不会自动发送消息或绕过验证码。

输入框已有其他草稿时，插件会拒绝覆盖；请先保存或清空原文。页面中找不到唯一输入框时，请手动复制草稿。

还通过本地模拟 HTTP 服务，在浏览器中验证获取模型、关键词筛选、选择后自动填写保存、使用所选模型测试连接，以及重开后恢复模型和密钥。该测试使用虚构密钥和模型，不等同于真实中转站验证。

尚未使用真实 API Key 验证任何官方、厂商或中转站服务，也未在登录后的 BOSS 聊天页面完成端到端验证。请在 Edge/Chrome 重新加载插件；原本已保存的简历资料会保留。

## 源码与本地数据

仓库仅包含通用源码和说明，不包含用户简历、联系方式、真实岗位清单、聊天记录或 API Key。用户在浏览器中填写和保存的数据不会修改源码文件。
